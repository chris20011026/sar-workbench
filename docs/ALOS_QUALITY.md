# ALOS 跨衛星相容性與匹配品質

本功能隨 alosStack「讀取後統一取樣」使用；不改動未啟用此選項的原流程，也不對已完成的專案補跑科學運算。

## 兩個不同的檢查

### 讀取後：相容性資訊

影格檢查頁除了外框與振幅，也列出本次處理影格的波長、名目距離頻寬、處理器記錄頻寬、原始 RSR／PRF，以及 Doppler 近似式的常數與一次項。每列可展開資料來源、格式位元組與換算定義。候選影格不納入本次摘要，缺漏或不支援的資訊顯示「未知」，不以零取代。

名目共同頻帶以有效波長換算載頻 `c/λ`，再用線性調頻率與脈衝長度計算名目頻寬，估算矩形頻帶交集。僅對完整的已辨識 Stripmap Level 1.1 產品使用；它未包含幾何造成的頻譜位移、實測頻譜或共同方位頻帶，**不等於已完成共同頻帶濾波或證明可以干涉**。兩種頻寬分欄保留，避免混淆定義。

Doppler 顯示 `f_D(R_km) = a + b × R_km` 的係數，常數不是影像中心像素的 Doppler。原始 LED 的取樣資訊也不一定等於讀取器換算值或統一取樣後的值，處理值另見取樣表。

格式來源：[JAXA PALSAR-2 CEOS](https://www.eorc.jaxa.jp/ALOS/en/alos-2/pdf/product_format_description/PALSAR-2_xx_Format_CEOS_E_g.pdf)、[JAXA PALSAR-3 CEOS](https://www.eorc.jaxa.jp/ALOS/en/alos-4/pdf/FTR-240031A_ALOS-4_PALSAR-3_StandardProduct_Format_CEOS_En.pdf)。名目頻寬定義對照 [ISCE2 ALOS2 reader](https://github.com/isce-framework/isce2/blob/main/components/isceobj/Sensor/MultiMode/ALOS2.py)。

### 匹配後：干涉前先停下來

「開始匹配，完成後先檢查品質」只完成 cmd1 剩餘步驟。工作台讀取各比較日期／影格／子波束的 `ampcor.off`、`cull.off`，產生匹配品質報告並停在 `matching_review`，此時沒有執行 cmd2。

| 畫面欄位 | 用途與限制 |
|---|---|
| 輸入與保留點數、剔除比例 | 有原始相關匹配點且保留點確實為其子集時才顯示剔除比例。全部保留也可能是 ISCE2 剔除不足後退回原始點，須看日誌。 |
| 距離／方位偏移 | 顯示最小、中位、最大值，單位為像素。這是影像對位量，不是地表位移。 |
| 匹配點位置散點圖 | 每影格最多 100 個保留點的等間隔抽樣，顏色可切換距離／方位偏移；統計仍使用全部保留點。座標為參考影像像素，不是地理地圖。 |
| 診斷擬合殘差 RMS | 用保留點另外擬合一階平面，分別顯示距離／方位殘差；不是 ISCE2 實際二階模型的誤差，不以單一數值自動判定精度。 |
| 幾何／來源待確認 | 缺少 ampcor 原始證據時，不把 cull.off 冒稱為相關匹配；使用者須結合幾何、日誌及後續相干性判讀。 |
| 缺少／無效證據 | 沒有有效保留點、格式錯誤或來源不一致時，不能繼續。 |

確認內容後，填寫判讀依據並勾選，再按「確認匹配品質，開始干涉處理」。該次同意會綁定報告、取樣計畫、來源與偏移檔案指紋。頁面重新載入不會自動同意；修改證據後須按「更新品質檢查」並重新判讀。更新只重新讀取現有診斷，不執行科學處理。

報告保存於 `proc/helper_matching_quality.json`，人工確認保存於 `proc/helper_matching_approval.json`。中斷時遵循[恢復中心](RECOVERY.md)的副本與來源檢查；新的匹配階段復原完成仍須經過品質關卡。舊版已開始後續階段、未建立新報告的復原點沿用舊版流程，不憑空要求不存在的診斷產物。

## 驗證範圍

控制測試涵蓋缺失／格式錯誤、來源變動、不同意不續跑、更新撤回舊確認與復原次序。合成偏移點測試核對統計及診斷模型。五日期真實 ALOS-2／ALOS-4 資料只用於唯讀中繼資料核對，專案仍停在影格人工確認；未因此進行真實重取樣、匹配、干涉或位移驗證。

缺少相容的真實 SLC、影格地理對應或研究者判讀時，網站仍可查看設定及診斷，但不能將軟體測試通過當作科學成果通過。
