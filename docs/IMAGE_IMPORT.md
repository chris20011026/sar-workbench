# ALOS-2 影像資訊與覆蓋圖

在「開始使用 → 準備我的 ALOS-2 資料」選資料夾或 ZIP，再按「檢查這批資料」。可選擇辨識環境；預設優先使用已驗證的工作台工具，其次既有 ISCE2 環境。讀取在隔離的子程序執行，不修改來源、Conda 套件或既有處理專案。

## 讀取哪些資訊

- 檔名初步辨識日期、frame、極化、Level 1.1 產品模式和 LED／IMG 配套。
- 沿用所選 ISCE2 的 `isceobj.Sensor.CEOS.CEOSDB` 與 `alos2_slc` schemas，讀取 LED 的場景編號、中心時間、升降軌、左右視、絕對軌道圈次、感測器描述與模式碼。
- IMG 的日期、極化、尺寸、記錄長度與檔名、LED 交叉核對。不符或檔案截斷時阻止匯入。
- 未壓縮 IMG 只讀檔頭與九條分散的影像記錄前綴，使用首末像素座標描繪左右邊界；不读取 SLC 像素、不啟動對位或重新地理定位。座標按 JAXA 規範的微度及有號整數處理。
- ZIP 只讀 LED 與 IMG 前部，避免為了最後一行而解壓整幅影像。此時顯示「範圍未確認」；整理展開完成後再補讀邊界、核對分組，將報告保存為匯入目錄的 `inspection.json`。補讀失敗的工作不作為完成結果，原始 ZIP 保留。

正式格式依據：[JAXA CEOS Rev G](https://www.eorc.jaxa.jp/ALOS/en/alos-2/pdf/product_format_description/PALSAR-2_xx_Format_CEOS_E_g.pdf)，Table 3.3-5、3.3-13、3.3-14；讀取器沿用 [ISCE2](https://github.com/isce-framework/isce2)。部分 Level 1.1 的場景中心為空白，ISCE2 會解析成零；本功能不將零值當成位置。

## 如何分組與看圖

可勾選要納入的日期／frame 再重新核對；不同升降軌、視向、感測器描述或產品模式會列出不同候選組，使用者可以選一組重新核對。沒有共同極化、同一天 frame 來自不同軌道圈次、日期之間沒有共同概略覆蓋、日期/frame 配套不符時，不能直接整理成一個可用專案。

候選組不是「已證明同一相對軌道」：目前只顯示絕對軌道圈次，不推算相對軌道。共同覆蓋只是各日期影像邊界多邊形聯集之間的交集，不是共同有效像素或相干性遮罩。不同圈次跨日期本來就可能組成時間序列。實際相容性仍需 ISCE2 幾何、對位與後續科學品質檢查。

地圖可以切換日期、點選 frame、疊上全部日期的共同概略覆蓋。預設不連線取得底圖；選擇 OpenStreetMap 後會向該站請求目前的觀看範圍，不上傳 SAR 檔案。網路底圖不可用時保留本機邊界。

## DEM／WBD 與 MintPy 範圍

全部影像邊界都可辨識時，可按「帶入全部影像範圍 + 緩衝」，以影像聯集的外框加四邊各 0.1° 填入地形下載欄位。仍需核對並預覽，再明確啟動下載；緩衝是實用預設，不保證所有地形或產品的定位誤差。

匯入精靈會比較既有 DEM／WBD 描述範圍與影像外框；不足時不讓使用者帶入下一頁。這是概略範圍檢查，不替代處理前檢查。後續 MintPy AOI 是另外的研究範圍，不拿它替代完整影像所需的 DEM。

## 目前邊界

以 ALOS-2 CEOS Level 1.1 Stripmap 為第一個支援案例。其他模式或命名方式不保證支援，尤其 ScanSAR 多子條帶產品不在這次完整驗證範圍。高緯度（絕對緯度達 85°）、跨換日線、無效／缺漏座標不自動產生範圍；沒有 ISCE2 時只顯示檔名清單並標明未核對。此版不以軌道加 DEM 推導缺少的邊界，也不自動下載衛星影像。

測試使用合成 CEOS 描述檔涵蓋南／西半球、分組衝突、極化／日期矛盾、截斷檔案、ZIP 展開前後與實際 upstream decoder；另以本機既有研究資料唯讀確認。不將研究影像、個人路徑或報告上傳到 GitHub。
