# 統一工作空間

此頁說明 **v0.7.0-beta.1** 的入口整合，已納入新版 Mac 下載包。這次整合沒有升級科學套件，也沒有把 ISCE2 與 ISCE3 合併到同一個環境。

## 四個入口

| 入口 | 用途 |
| --- | --- |
| 專案總覽 | 查看 ISCE2、MintPy／品質報告、NISAR、格式轉換和最近十筆資料準備紀錄；依名稱、路徑、狀態或類型篩選，開啟既有工作的目前階段 |
| 建立專案 | 選填資料辨識，再依兩期比較、多日期分析或資料準備選流程；熟悉資料的使用者可直接選流程 |
| 資料與成果 | 讀取資料描述，查看 ALOS／NISAR 產品與已有 GUNW 成果 |
| 工具與環境 | 區分既有科學環境、基本驗證結果和工作台專用工具；保留原有教學、匯入與地形準備功能 |

總覽只彙整原本的紀錄，沒有搬移專案、修改科學設定或自動重跑。離線磁碟或搬移後無法找到的專案仍保留於清單，不會被當成沒有工作。MintPy 從已完成的 alosStack 專案建立分析版本。

## 移除不再使用的專案

ISCE2 專案卡片提供「從工作台移除」，包含顯示「位置無法讀取」的專案。確認名稱與路徑後按「移除紀錄」，專案和所屬 MintPy／品質報告會從總覽隱藏。這只更改工作台登記，不刪除影像、成果或 Conda 環境。

誤按時可立即按「復原清單紀錄」，或重新開啟工作台後，展開總覽底部「已移除的專案」復原。復原資訊保存在工作台狀態資料夾 `removed-projects/`；已由 Finder 刪除的磁碟檔案無法靠此功能救回。正在執行或仍有背景程序的專案不能移除。

## 外接硬碟與專案管理

ISCE2 專案卡片和專案內頁都有「管理專案」。可修改顯示名稱、研究備註，查看專案及來源影像、DEM、WBD 的連線狀態。名稱與備註保存在本機工作台登記，不更改資料夾、XML、處理指令或檢查點。

| 情況 | 工作台的處理方式 |
| --- | --- |
| 外接硬碟或已掛載 NAS 暫時離線 | 保留名稱、備註、原位置和最後處理階段，顯示「儲存裝置未連線」 |
| 同一磁碟接回原位置 | 總覽與管理視窗約每 5 秒重新檢查，確認專案代號後恢復顯示；可按「重新檢查連線」立即更新 |
| 同一磁碟掛載位置改變 | 以磁碟識別及原相對路徑尋找專案，再核對專案代號；顯示「已找到新位置」，由使用者確認重新連結 |
| 磁碟同名但身分不同 | 不自動開啟，避免把同名資料夾當成原專案 |
| 專案搬到其他磁碟、資料夾改名，或未取得固定磁碟識別 | 在「重新連結專案資料夾」使用系統資料夾選擇器；核對代號後確認 |
| 磁碟確定不用了 | 從工作台移除登記；保留原磁碟資料 |

首頁的「加入既有專案」可加入以前由工作台建立的 ISCE2 專案（需要 `.helper/state.json` 與 `proc`）。只登記位置，不複製大型影像、不啟動運算；相同代號不會重複列出。這不等於匯入任意手動 ISCE2 的 `proc` 或 XML。NISAR 與 ALOS-4 轉換仍由各自的工作紀錄管理。

**找到專案與接續運算是兩個檢查。** 原位置接回後可依原流程使用；實際位置改變時可以重新連結、查看既有紀錄及可讀的成果，但禁止直接啟動原科學流程或新增反演。ISCE2 指令、VRT、連結與檢查點可能保留絕對路徑，不能僅換清單路徑就視為可安全續跑。這版不自動改寫它們；需恢復原位置，或以新位置建立處理專案。既有成果若仍依賴舊路徑，也需先恢復那些來源。

運算中仍應保持磁碟連線。儲存位置中斷後，工作台盡可能在本機保存失敗紀錄並解除工作鎖，不會自動接續或宣稱半成品有效。狀態寫入不會重建已消失的專案目錄。這不是對意外拔除的檔案完整性保證。

磁碟識別只讀取掛載資訊：macOS 使用卷宗 UUID，Linux 使用 `/dev/disk/by-uuid`；網路分享以不含登入資訊的伺服器／分享位置雜湊辨識。不掃描整顆硬碟的影像、不自動掛載 NAS，也不改 Conda 環境。工作台需先在磁碟連線時讀取過專案，才能記住可靠位置。新登記資訊保存在工作台狀態資料夾 `project-details.json`；中斷紀錄放在 `interrupted-projects/` 或 `interrupted-analyses/`。分析中斷只標記該分析版本，不改已完成的原 ISCE2 專案狀態。

測試涵蓋離線、接回、掛載位置變更、同名不同磁碟、錯誤專案代號、未取得 UUID、重複副本、來源磁碟離線及中斷保護；另以 macOS APFS 測試映像驗證真實掛載資訊與介面。這些驗證不包含實體 USB 意外拔除、所有 NAS／檔案系統或新 SAR 科學運算。

## 資料辨識與流程選擇

選擇產品資料夾、SAFE、ZIP 或 HDF5，按「辨識並篩選流程」。只讀取正式描述資料與必要標頭，不載入整幅影像。資料夾辨識限制為四層子目錄、5,000 個項目和 64 個候選產品；資料過多時請縮小範圍。

- ALOS-2 CEOS 導向雙日期／多日期設定；ZIP 可先使用原有日期整理精靈。
- Sentinel-1 必須由正式描述檔確認為 S1A／S1B IW SLC；GRD 不會導向 topsApp。改名為一般名稱的 ZIP 也會檢查 SAFE 內容。
- NISAR RSLC 導向 ISCE3 雙日期表單。恰有兩份 RSLC 時依日期帶入，GUNW 則提示查看既有成果。
- 含 ALOS-4 的資料先進入格式與相容性檢查，不自動啟動混合衛星干涉。日期、影格對應、取樣率與共同覆蓋仍需確認。
- 混合不同衛星的集合不直接啟動科學流程。辨識完成也不等於已符合共同軌道、極化、完整性或空間條件，建立專案後仍須健檢。

八個入口的成熟度分別標示。ALOS-4 入口是「僅資料準備」；尚未實作的 topsStack、stripmapApp 和 stripmapStack 保持停用。這次整合不增加這些模式的科學支援範圍。

## 環境狀態

「已偵測」只表示找到對應套件或入口。使用者按「驗證這個環境」後，才會在該 Conda prefix 啟動隔離的檢查程序，檢查 Python、套件架構標記、套件匯入、流程入口、GDAL 和繪圖依賴。NISAR 另檢查 ISCE3 0.25.21 的完整 workflow 匯入及 GDAL HDF5 driver。ISCE3 的成果繪圖函式庫是選用項目，缺少時會明確標示，可在資料瀏覽器選擇具繪圖功能的環境；不影響該環境的 NISAR 處理入口驗證。

驗證只寫入工作台的狀態與暫存資料，不安裝或更新環境套件。驗證紀錄位於 `state-dir/environment-checks/`，含時間與檢查項目；Python、Conda 套件記錄、主要入口或驗證規則變更後，會提示重新驗證。有運算或安裝工作進行時，暫不啟動環境驗證。

**基本驗證通過不等於科學全流程已驗證。** 架構檢查是 Conda 套件標記檢查，不是掃描每個二進位檔。專案健檢、運算工具實測與成果品質判讀仍然必要。

「工作台專用工具未安裝」只描述額外的固定版本安裝，不代表電腦沒有 ISCE。既有環境可用於專案；合成教學和公開地形下載目前仍使用工作台專用工具。

## 驗證範圍

- 自動測試涵蓋多來源工作彙整、狀態與代號區隔、離線專案、格式辨識、混合衛星關卡、驗證快取失效、端點授權和工作互斥。
- 使用課程資料確認 NISAR 日期帶入與混合 ALOS 資料辨識；使用合成工作紀錄測試跨流程跳轉、篩選與錯誤呈現。
- 沒有為這次介面整合執行整幅 RSLC 干涉或跨衛星 ALOS 處理；各流程原有的實驗限制維持。

## 專案儲存空間

「管理專案」新增「專案資訊／儲存空間」分頁。空間面板區分影像、ISCE2、MintPy、恢復副本、預覽快取等容量，並列出各磁碟可用空間。背景統計可停止，不影響科學運算；不會自動刪除或搬移資料。外部來源另列，避免當成專案獨占容量。計算規則、離線紀錄及限制見[空間統計說明](STORAGE_USAGE.md)。

已完成的 ISCE2 專案可使用「管理專案 → 安全搬移」。詳見[搬移精靈](PROJECT_MIGRATION.md)。
