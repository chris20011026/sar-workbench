# alosStack 讀取後統一取樣（Stripmap 試用）

新建 **ALOS-2 多日期** 專案時，在「處理設定 → 影格與取樣」勾選「讀取後統一取樣」。這個選項預設關閉；既有專案維持原流程，不會自動改寫已完成的成果。

ALOS-4 原始產品須先使用資料準備功能轉成受支援的 PALSAR-2 格式副本，再按 `YYMMDD` 整理完整轉換輸出（VOL、LED、TRL、各極化 IMG 與 `conversion.json`），並保留原始 ALOS-4 來源可讀。本功能不會自動決定 ALOS-2 與 ALOS-4 的影格對應，也不把格式轉換視為科學驗證。

轉換後的檔名使用合成軌道／影格標籤。確認頁會回查原始 ALOS-4 的軌道、姿態、觀測時間、取樣率等保留欄位，核對成功後才將這類檔名差異視為格式相容事項；缺少來源、描述不一致仍會阻擋。這是有界中繼資料檢查，不取代轉換階段的完整複數樣本比對。跨 ALOS-2／ALOS-4 建案只在啟用取樣統一的人工關卡流程中放行。

## 在網頁操作

1. 掃描來源資料。若部分日期有 0480、0490，但另一些只有 0480，可在影格清單選擇 0480；這只是讀取選擇，**不代表兩顆衛星的 0480 地理位置必然相同**。缺少指定影格的日期會被阻擋。
2. 勾選取樣統一、選參考日期，完成原有 DEM／WBD 與處理設定，建立並準備專案。
3. 按「讀取資料，前往影格與取樣檢查」。工作台只執行生成 cmd1 中的 `read_data.py`，接著顯示各日期／影格的 RSR、PRF、SLC 尺寸、虛擬來源與預計新增檔案量。
4. 影格外框與日期清單會自動載入；可切換日期、影格，或與參考日期並排查看振幅。若目前只讀取 0480，可另外選擇含 0490 的「候選影格資料夾」供比較，這不會改動本次處理影格。人工核對各日期對參考日期的涵蓋、軌道及拼接安排，填寫確認依據並勾選確認；不知道時就保留在這個關卡。
5. 按「確認影格，僅統一取樣」。工作台完成重取樣並核對產物後，再次停下，顯示「取樣統一已完成」。此時尚未執行基線或影像匹配；可以先檢查取樣後的尺寸、取樣率與影像預覽。
6. 檢查成果與相容性摘要後，另按「開始匹配，完成後先檢查品質」。工作台重新核對取樣完成紀錄與實際 SLC，只執行 cmd1 的剩餘步驟（包含基線與影像匹配），之後停在匹配品質關卡，不會自動跑 cmd2。
7. 查看匹配點數、保留比例、偏移分布及獨立診斷擬合殘差。填寫依據並按「確認匹配品質，開始干涉處理」，才接續原有 cmd2、cmd3 人工電離層檢查及 cmd4 流程。缺失、格式不符或證據變動時會阻擋續跑。詳見[相容性與匹配品質](ALOS_QUALITY.md)。

無須手動放置腳本或註解 `read_data.py`。原始 cmd1 保留供追溯；工作台只在自己的後續腳本排除讀取命令。未辨識的生成指令結構會停止，避免插在錯誤位置。

## 覆蓋地圖與振幅預覽

- 地圖使用 CEOS 中繼資料中的概略外框。實線為本次處理影格，虛線為候選；共同外框先合併各日期的選用影格，再計算日期間交集。候選影格及顯示開關不改變這個處理集合，缺少有效外框時不提供完整覆蓋結論。
- 外框不是有效 SLC 像素範圍，也不代表影像已配準。ALOS-4 轉換後的合成影格標籤會另作提醒。仍須研究者確認跨衛星地理對應、共同頻帶及其他處理條件。
- 底圖預設關閉，可選擇 OpenStreetMap 顯示道路與地名；只有開啟時才向圖磚服務請求目前地圖範圍，SAR 檔案留在本機。
- 振幅預覽從已核對的 MSB CEOS 或 LSB／MSB 實體 complex64 SLC 定距離抽樣，最大邊 768 像素，不把整張影像載入記憶體。這是點抽樣，沒有多視或斑點濾波；磁碟實際讀取量可能高於抽樣位元組數。
- 顯示尺度為未校正的 `20 log10 |SLC|`，每張影像各自按有效非零抽樣的第 2–98 百分位拉伸；零值與無效值透明。適合查看影像是否完整、辨識大範圍地物，不可直接比較輻射強度或相位。橫向為距離向像素、縱向為方位向像素，向上不代表北方。
- 統一取樣後可選「原始輸入」或「統一取樣後」影像，比較尺寸及外觀；參考日期未重新取樣仍會保留原資料。完成紀錄、來源指紋及 PNG 校驗均須有效，來源改變／離線會要求重新載入。

預覽及候選清單僅寫入專案 `.helper/sampling-review`，不會改動來源或勾選人工確認。檢查清單限所選資料夾與下一層產品／日期資料夾，一次最多 200 個影格；不會遞迴掃描整顆磁碟。

## 實際做什麼

- 參考日期保留原樣。每個比較日期的各影格／子波束，依參考對應單元的距離取樣率 RSR 與 PRF 重取樣；兩者差異均小於 1 Hz 時略過，沿用 ISCE2 的判斷門檻。
- 呼叫已選環境的 ISCE2 `contrib.alos2proc.resamp`，採用 `runPrepareSlc.py` 的線性座標縮放與尺寸計算。同時更新 swath 尺寸、取樣間距、PRF、Doppler 與方位 FM 多項式；三次式以 `p(ratio*x)` 直接轉換，避免建立大型座標陣列及再次擬合。
- `-virtual` 不需要事先生成實體 `.slc`。先驗證 `.xml`、`.vrt`、原始檔案長度、CFloat32 型別、位元序與 CEOS 列偏移，再由 ISCE2 直接讀取 VRT 指向的原始 IMG。需要重取樣的影像才生成新的實體 SLC。
- 對不在上游 nominal-rate 表中的合法 CEOS 距離取樣率，讀取程序以描述檔中的 MHz 換算。這個相容處理只存在於該次子程序，保留標準 ALOS-2 常數，不修改 Conda 套件或 shell 設定。

演算法依據：[ISCE2 runPrepareSlc.py](https://github.com/isce-framework/isce2/blob/main/components/isceobj/Alos2Proc/runPrepareSlc.py) 與 [alos2proc.py](https://github.com/isce-framework/isce2/blob/main/components/contrib/alos2proc/alos2proc.py)。上游的其他準備操作（例如共同頻帶濾波）不是本步驟的功能。

## 中斷與資料保存

新結果先寫到 `proc/helper_sampling/staged`，檢查尺寸、有限複數值與非全零內容後才替換 `dates` 中相應檔案。原始 SLC（如有）及描述檔移到 `proc/helper_sampling/before`，原始 CEOS 來源不修改。取樣相同的參考／其他影像不重寫。

多檔替換不是單一原子操作；使用 journal 與完成紀錄防止把中斷的半成品當成成功。失敗或拔除磁碟後會停止匹配，透過[恢復中心](RECOVERY.md)還原取樣前副本。請保留預設的復原保護；若自行關閉，未完成作業仍會保留備份並阻擋續跑，需要另行處理復原，不能按同一按鈕盲目重跑。

人工確認綁定當次讀取結果。小型描述檔使用 SHA-256，大型來源使用檔案長度與修改時間辨識（不是完整影像 checksum）。確認後若來源／描述檔改變，會阻止執行。完成取樣不會自動開始匹配；取樣階段失敗後從恢復中心重跑，成功時也會停在取樣成果檢查。成功結果再呼叫取樣步驟會先核對紀錄，不重複插值；已開始匹配及其後續階段的檢查點恢復也不重跑已完成的讀取與取樣。

## 驗證邊界

已用小型合成複數影像執行真正的 ISCE2 原生 resampler，檢查帶 CEOS 列填充的 MSB 虛擬來源、實體來源、升／降取樣、複數相位、係數轉換、原始檔案保留、不需取樣的略過、中斷發佈及過期確認。控制流程與瀏覽器測試另驗證人工關卡、不可自動選擇缺少的影格及續跑順序。

另以五期真實 ALOS-2／ALOS-4 Stripmap 資料驗證轉換來源核對、`-virtual` 讀取、取樣差異計畫及人工關卡停止；也驗證 5 個選用影格、3 個候選影格的外框及兩種感測器的唯讀振幅預覽。未執行這批資料的重取樣或匹配。取樣後預覽、獨立匹配確認與恢復行為以隔離合成資料及控制流程測試驗證。

目前只開放支援的 Stripmap 模式，ScanSAR burst／Spotlight 不適用此接法。這不等於完成跨衛星精密對位或完整 ALOS-2／ALOS-4 真實干涉驗證；頻帶相容性、影格對應、相干性、相位及最終位移結果仍需研究者核對。
