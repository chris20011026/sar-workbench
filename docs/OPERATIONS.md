# 日常操作、備份與故障排查

SAR 工作台在自己的電腦上執行。安裝完成後，開啟工作台、處理影像及查看成果都不需要 ChatGPT、Codex 或 AI 訂閱。科學判讀與人工確認仍由研究者負責。

## 每次怎麼開啟

| 安裝方式 | 開啟方法 | 運算時保持什麼開著 |
| --- | --- | --- |
| Mac App | 雙擊 `SAR Workbench.app`，按「準備並開啟工作台」 | App、運算電腦及資料磁碟 |
| 原始碼資料夾 | macOS 雙擊資料夾內的 `start.command`；需要既有 Python 3.10 以上 | 啟動後的終端機、運算電腦及資料磁碟 |

一般瀏覽器網址是 `http://127.0.0.1:8765/`；若啟動時指定其他連接埠，請使用啟動畫面列出的網址。它只連到目前這台電腦，不是可在其他電腦直接開啟的雲端網站。

關閉網頁分頁不會停止運算。需要查看時重新開啟原網址即可；不要因此再啟動第二套工作台。若提示「這個工作台已經在執行」，回到原本的頁面。結束 App／終端機前，先等待運算完成或使用頁面上的「停止工作」，確認工作已停止。

安裝、更新、影像／軌道／地形下載及網路底圖需要網路。資料與所需工具齊備後，本機成果檢視與不需要外部下載的處理可離線使用；不能保證每一種上游工作流都不再下載輔助資料。關閉底圖仍可看本機資料。

## 開始長時間運算前

1. 接好電源、外接硬碟／NAS，確認來源影像、DEM 與 WBD 都可讀取。請避免讓電腦休眠或闔蓋中斷運算。
2. 在專案確認頁核對資料、參考日期、極化、配對、環境及剩餘空間。黃色情況需閱讀限制，紅色問題先修正。
3. 需要中斷復原的 alosStack 專案，先查看「恢復中心」是否有啟用階段副本及足夠空間；它會保存完整 `proc`，不能當作零成本功能。
4. 用工作台啟動後，不要同時在終端機對同一個 `proc` 執行 cmd1–4，也不要更換該專案正在用的環境套件。

## 外接硬碟或 NAS 接回後

- 原磁碟接回原位置，總覽會定期重新檢查；也可按「管理專案 → 重新檢查連線」。
- 掛載位置改變時，工作台可能顯示「已找到新位置」。核對磁碟與專案後確認重新連結；沒有候選時，用「重新連結專案資料夾」選擇包含 `proc` 與 `.helper` 的那一層。
- 重新連結可以找回紀錄及可讀成果，但指令與描述檔可能仍含舊路徑。此時保留運算關卡；要續跑原流程須恢復原位置或建立新處理專案，不能只改清單位置便視為完成搬移。
- 若只是不要清單上的專案，選「從工作台移除」。這只移除登記，不刪影像；誤按可從「已移除的專案」復原清單紀錄。

搬移已完成專案請用[安全搬移精靈](PROJECT_MIGRATION.md)，並閱讀外部來源仍需保留的限制。磁碟不應在運算中拔除；自動找回位置不代表能修復寫到一半的檔案。

## 常見狀況

| 畫面或現象 | 可以先做什麼 |
| --- | --- |
| 網址打不開、`Failed to fetch` | 確認 App／啟動終端機仍在執行，核對網址與連接埠。若只是單一功能失敗，先記下錯誤與執行日誌；已有工作在跑時不要直接關閉 App。 |
| 找不到原生選檔視窗 | 在建立專案畫面的「檔案選擇方式」改用「網頁內建選擇器」。取消選檔不會修改已填路徑。原始碼版缺開發工具時可改用 Mac App；不需為選檔重裝科學環境。 |
| 專案顯示位置無法讀取 | 先連回來源磁碟／NAS，再「管理專案 → 重新檢查連線」。不要新建同名資料夾假裝原位置還在。 |
| 缺工具、環境驗證失敗 | 在「工具與環境」檢查所選環境與詳細紀錄。確認使用完整、同架構的 ISCE2 環境；不要直接更新正在用的環境或把 ARM／Intel 套件混入。 |
| 磁碟空間不足 | 停止新增工作，在「管理專案 → 儲存空間」查看占用。先備份；不要任意刪 `proc` 中間檔、`.helper` 或復原副本。 |
| 正式運算失敗／中斷 | 先保留錯誤和日誌，再進「恢復中心」診斷。修正來源、空間等原因後，有有效副本才依畫面確認復原；不跳過失敗步驟或手動改狀態為完成。 |
| 結果圖沒有點、顯示無資料 | 先核對選到的分析版本、有效覆蓋、遮罩及點位；空白不等於零位移。檢查品質報告，避免先重跑整個 ISCE2 流程。 |

「恢復中心」主要支援 alosStack 階段副本，並非所有雙日期、MintPy、NISAR 工作共用的重試工具。沒有可驗證副本時保留診斷與半成品，另建工作版本比直接覆寫可靠。詳見[復原條件](RECOVERY.md)。

## 要備份什麼

請在沒有運算、搬移或安裝工作時備份。至少保存：

1. **原始影像、DEM、WBD 和轉換來源紀錄**：留意專案可能只連結這些檔案，複製專案不一定複製了來源。
2. **完整專案資料夾**：包含 `proc`、分析成果及隱藏的 `.helper`。只備份圖片不能重現處理。
3. **工作台登記與工作紀錄**：預設在 `~/.local/share/alosstack-helper`；使用自訂 `--state-dir` 時備份自訂位置。這裡保存清單、備註與部分作業紀錄。Finder 可用「前往檔案夾」開啟。
4. **安裝版與研究環境版本紀錄**：保留使用中的 App／程式碼版本、下載說明及環境驗證紀錄。不要用備份的環境任意覆蓋另一個路徑中的 Conda 環境。

專用工具預設在 `~/sar-workbench/runtime`，是正在使用的工具，不是可隨意清除的快取。`imports`、`terrain`、`lessons`、`projects` 也可能含實際資料；若啟動器選過其他位置，以所選位置為準。能備份整個工作台資料位置更方便，但仍須另外保留外部來源磁碟。

## 如何更新，才不打斷研究

1. 完成或停止所有工作，記下目前 App／程式碼版本，備份上述資料。
2. 閱讀 [GitHub 版本說明](https://github.com/chris20011026/sar-workbench/releases)。主分支有新程式不代表已有新版安裝包；不要把 `Source code` ZIP 當成 Mac App。
3. Mac App 使用者保留舊 App 作為備份，再開啟新版本；原始碼使用者先保留原程式資料夾與本機修改，再將新版本放到另一個資料夾。只啟動一套工作台，並沿用原本的工作台資料位置與狀態目錄。
4. 先看專案總覽、既有成果及環境驗證，再建立小型測試專案。更新工作台程式不代表要同步更新研究環境，尤其不要在運算途中更換環境。
5. 若有問題，先停止新版本、保留錯誤紀錄。舊 App／程式碼只能在資料格式相容時回用；若新版已修改狀態資料，不要直接兩版交替寫入同一份紀錄。

本機的程式碼、研究資料和科學環境都獨立於 AI 訂閱，訂閱到期不會自動刪除或停用它們。下載來源及上游科學套件的使用條件仍以各自授權為準。

## 解除安裝與保留成果

Mac App 啟動器提供「解除安裝運算工具…」。先停止並結束工作台，再重新開啟啟動器，核對移除的 `runtime` 路徑後移至垃圾桶；研究專案、匯入資料及外部 Conda 環境保留。移除 App 本身可將 `SAR Workbench.app` 移到垃圾桶。

不要以刪除整個 `sar-workbench` 資料夾代替解除安裝，它可能包含研究資料。清空垃圾桶前再次確認，詳見[首次使用指南中的解除安裝](FIRST_USE.md#與既有-isce-共存及解除安裝)。

## 校正後及分析中途停下來是正常的

新版 alosStack 套用電離層校正後會先停下，cmd4 結束後再進行成果驗收。MintPy 在解纏診斷及殘差／日期判讀也會等待確認。請先查看診斷、填寫判讀理由，再操作目前關卡的繼續按鈕；重新整理頁面不會同意或開始運算。詳見[各關卡操作](REVIEW_GATES.md)。

舊版已完成的專案及分析維持可讀，不會自動補跑新關卡。新流程的「已完成」也不代表所有科學品質均已證實。

## 什麼仍需要人工判斷

影格外框與振幅預覽能幫助檢查資料，但不能證明跨衛星對位或干涉品質。ALOS-2／ALOS-4 保留影格對應與取樣檢查，不能僅憑相同影格編號繼續。電離層排除配對、MintPy 穩定參考區與最終位移解讀也需研究判斷。

「程式測試通過」、「環境可使用」與「真實影像科學結果已驗證」是不同層次。Sentinel-1 IW SLC、NISAR RSLC 與 ALOS-2／ALOS-4 混合流程請依各功能頁的驗證狀態使用。LOS 位移是衛星視線方向的相對位移，不能直接當作垂直沉降。
