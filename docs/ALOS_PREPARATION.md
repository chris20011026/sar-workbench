# ALOS 批次資料準備

在「建立專案」選 ALOS 資料準備，或從總覽接續先前紀錄。這個入口沿用所選的 ISCE2 Conda 環境，不需要 ISCE3，不修改環境套件。資料準備與實際跨衛星干涉分開記錄。

## 1. 掃描日期與影格

選擇包含各日期產品的父資料夾及 ISCE2 環境，按「掃描資料」。程式讀取正式 CEOS 中繼資料，列出 ALOS-2／ALOS-4、日期、極化、影格、格式、可轉換狀態與外框來源。可掃描巢狀資料夾，單次最多 256 份產品；ZIP 應先解壓縮。

ALOS-2 保留原本格式。ALOS-4 必須是支援的高解析度 Level 1.1 Stripmap 完整產品，包含 VOL、LED、TRL 和對應 IMG。ScanSAR、Spotlight、不同級別或不完整產品會保留原因，不自動修補。缺少可信座標會標示「未確認」，不從檔名或中心點推測外框。

## 2. 建立格式副本並檢查

1. 勾選要轉換的 ALOS-4 產品。
2. 從 [JAXA 官方資料頁](https://www.eorc.jaxa.jp/ALOS/en/alos-4/a4_data_e.htm)取得 `P3toP2snap`，在介面選擇其資料夾。工作台核對已審閱版本的 SHA-256；不散布或自動執行不明版本的腳本。
3. 選擇輸出父資料夾並填入全新資料夾名稱。頁面顯示所選副本大小，開始前檢查可用空間。原資料夾、工具及科學環境不能作為覆寫目標。
4. 核對後開始。產品依序執行；逐份顯示轉換、檢查、完成或失敗。某份失敗不會把其他產品標成失敗，完成的產品保留。

每份副本包含 `ALOS2_format/`、`conversion.json` 及 `quality.json`；批次父目錄保存結果清單。檢查包括：

- 檔案集合、Level、極化、行列數和 CEOS 記錄結構。
- 每一個複數樣本的位元組比對；逐塊讀取，不把整幅 GB 級影像載入記憶體。
- 所選環境的實際 ISCE2 LED／IMG 中繼資料讀取。
- 來源與輸出的指紋及處理前後變動檢查。

「檢查通過」只表示格式、樣本保存和讀取檢查通過，不表示干涉、對位或科學品質通過。P3toP2 不做重採樣、拼接或跨衛星對位。

停止或斷線會保留紀錄與半成品。返回總覽即可重開準備紀錄；按「勾選需重試項目」，選另一個全新輸出位置再執行。完成項目不能直接重跑或覆寫；來源變更需要重新掃描。使用外接硬碟時請保持連線，重新掛載或路徑改變後先核對資料，不把半成品當作成功副本。

## 3. 覆蓋地圖與人工確認

A／B 組各選日期及影格。同一天有兩個影格時可以一起選，查看合併外框、兩組交集、各自覆蓋比例及逐影格比較。兩組合計最多 64 份產品。地圖預設離線；選擇 OpenStreetMap 才連線取得目前範圍的圖磚，SAR 原始影像不會上傳。

外框取自正式產品中繼資料，屬於覆蓋近似。即使重疊，也不能證明有效 SLC 像素、共同頻帶、取樣率、相位或對位相容。只要選定產品有未知外框，整組比例就顯示未知；不同軌道、方向或極化會顯示檢查資訊。

閱讀後可保存「待確認」、「已確認對應」或「不相容」，並填寫評閱人與理由。來源或影格選擇改變時，既有確認失效。**儲存確認不會開放混合 ALOS-2／ALOS-4 InSAR 或自動拼接**；後續仍需要獨立科學驗證。

## 紀錄與分享

頁面可下載可列印 HTML 和完整 JSON，包含產品、參數、來源指紋、轉換檢查與人工確認。紀錄保存在工作台 state-dir 的 `alos-preparation/<id>/`。報告可能包含本機絕對路徑；自行檢查後再分享。原始影像和 JAXA 工具不放進 GitHub。
