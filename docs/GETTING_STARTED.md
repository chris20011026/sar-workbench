# 從零開始：資料準備與第一個專案

這份指南回答三件事：**需要什麼資料、應該放在哪裡、接下來按什麼**。網頁中的「從零開始」也提供相同路線的互動準備清單。

你不必先會操作 ISCE2、編輯 XML，或手動修改 cmd1–4。工作台負責產生設定與指令；資料選擇、處理參數及科學判讀仍需由你確認。完成準備清單不會自動批准任何人工檢查關卡。

## 1. 還沒有安裝或資料，從這裡開始

1. 目前一鍵安裝適用 **Apple Silicon Mac，macOS 14.5 或更新版本**。從 [GitHub Releases](https://github.com/chris20011026/sar-workbench/releases) 下載 `SAR-Workbench-版本-macOS-arm64.zip`，不是頁面下方的 Source code ZIP。
2. 解壓、開啟「SAR 研究工作台」，選「準備並開啟工作台」。目前 macOS 應用程式的支援與安全性提示見[首次使用](FIRST_USE.md)。
3. 在「工具與環境」按「安裝並驗證運算工具」。目前一鍵安裝提供 ISCE2、MintPy、SNAPHU 等工具；已有可用環境也可選用。**NISAR 所需 ISCE3 要另外準備**。
4. 工作台專用工具環境準備好後，沒有衛星資料時可開啟「先跑一個小範例」，按「執行教學範例」。它以合成干涉資料執行 MintPy，讓你熟悉速度圖與位移曲線；不是原始 SAR 前處理或真實地區的研究結果。只選外部既有環境，不會開啟這項管理範例。

工具與下載快取先預留至少 12 GB。真實 SAR 影像、中間產物與備份另計，常需要數十至數百 GB；實際需求依日期數、影格數與處理設定而定。長時間運算請保持供電與磁碟連線，避免讓電腦睡眠。

## 2. 先選正確路線

| 手上的資料／想做的事 | 工作台入口 | 現況 |
| --- | --- | --- |
| 多日期 ALOS-2 Level 1.1 Stripmap，後續想做 MintPy | ALOS-2 多日期／alosStack | 主要新手路線，下面有詳細教學 |
| 兩期同模式 ALOS-2 Level 1.1 Stripmap | ALOS-2 雙日期／alos2App | 試用；不是時間序列 |
| 兩期 S1A／S1B IW SLC | Sentinel-1 TOPS 雙日期／topsApp | 試驗流程；仍待真實影像端到端驗證 |
| Sentinel-1 多日期 | topsStack | 尚未開放執行 |
| 其他感測器的通用 Stripmap 雙日期 | stripmapApp | 尚未開放執行 |
| 通用 Stripmap 多日期 | stripmapStack | 尚未開放執行 |
| ALOS-4 高解析度 Level 1.1 CEOS | ALOS 資料準備 | 先轉換格式；混合衛星仍有人工影格關卡 |
| 兩期 NISAR L-band RSLC HDF5 | NISAR 試驗流程 | 獨立 ISCE3 環境；非目前一鍵新手環境 |
| 已完成的標準 alosStack 結果 | 匯入手動 ISCE2 成果／匯入可攜分析包 | 從品質檢查接續新的 MintPy 分析 |

不確定檔案種類時，可以先用「建立專案」中的「辨識我的資料」。辨識結果協助選流程，不能代替後續完整性與科學品質檢查。六個 ISCE2 模式出現在介面中，不表示六個都已實作。

## 3. 資料夾怎麼放

建議把**原始產品、地形資料、工作成果**分開。以下名稱都是範例，可放在本機或外接 SSD／已掛載的 NAS：

```text
SAR_workspace/
├── raw/                         # 你保存的完整原始產品
│   ├── product_date1_frame0480/
│   │   ├── LED-…
│   │   ├── IMG-HH-…
│   │   ├── summary.txt
│   │   └── 其他原始檔案
│   ├── product_date1_frame0490/
│   │   ├── LED-…
│   │   ├── IMG-HH-…
│   │   ├── summary.txt          # 同名檔各留各的
│   │   └── 其他原始檔案
│   └── product_date2.zip
├── terrain/                     # 若已經有 DEM / WBD
│   ├── region.dem.wgs84
│   ├── region.dem.wgs84.xml
│   ├── region.dem.wgs84.vrt
│   ├── region.wbd
│   ├── region.wbd.xml
│   └── region.wbd.vrt
└── projects/                    # 新專案的父位置
    └── my_first_stack/          # 由「建立專案」建立
        └── proc/               # 由工作台管理，不用預先建立
```

- 原始產品保留完整，維持原檔名；不要把不同產品的全部檔案攤平到同一層。兩個影格都有 `summary.txt` 時，留在各自產品資料夾，無須挑一份覆蓋另一份。
- 新手 ALOS-2 匯入器可以掃描巢狀資料夾與 ZIP。它只整理處理所需的 LED／IMG，不合併或覆蓋原始 summary。
- 已解壓來源通常透過**連結**供工作台使用，並非完整複製；原外接硬碟／NAS 必須保持可讀。ZIP 中的必要影像則解壓到管理區。
- 預設管理區為 `~/sar-workbench`，匯入資料通常在 `imports/匯入代號/YYMMDD/`。自訂工具根目錄時，以實際選擇的位置為準。
- 來源與專案不能互相包含。建議用 `/Volumes/SAR_SSD/sar-data` 與 `/Volumes/SAR_SSD/sar-projects` 這樣的同層位置，或使用 `~/sar-data` 與 `~/sar-workbench/projects`；不要把新專案建在原始來源裡。
- ISCE2 會產生處理指令，**實際處理來源、環境、DEM／WBD、專案的完整路徑**需使用英文字母、數字、底線、連字號、句點與目錄分隔符，避免空格或中文。磁碟與上層資料夾名稱也算在路徑內。專案顯示名稱可以用中文。
- 原始產品不必為了掃描而改名：ALOS-2 匯入器可先讀取中文或含空格的原始位置，再整理到管理區。是否能開始處理仍以實際來源與工作路徑的檢查結果為準。
- 不用預先建立 `proc`、編輯 `alosStack.xml` 或下載別人的 cmd1–4。選新的工作位置後，工作台會依你的表單產生它們。

### 外接硬碟注意事項

拔除磁碟造成「位置無法讀取」不等於專案被刪除。接回後先重新檢查；若掛載名稱或路徑變了，使用「重新連結」。要更換存放位置，使用「安全搬移」並先停止運算。原始影像與 DEM／WBD 所在磁碟都要保持連線。只有連結的工作資料夾不是備份，勾選複製也不保證已把所有連結變成實體檔；參考[專案管理](WORKSPACE.md)、[安全搬移](PROJECT_MIGRATION.md)及[可攜分析包](PORTABLE_PROJECT.md)。

## 4. ALOS-2 多日期：最完整的第一個專案路線

### 準備 A：完整且相容的影像

需要 **ALOS-2 Level 1.1 Stripmap 的 CEOS 複數資料**。每個產品至少應有互相對應的 `LED-…` 與所選極化的 `IMG-HH-…` 等影像；仍應保留完整原始產品，以便追溯。Level 1.5／2.1、瀏覽圖、全球鑲嵌圖與一般 GeoTIFF 不可替代 Level 1.1 輸入。

第一次建議使用課程或研究室已確認相容的一批資料。核對：

1. 日期不同，且涵蓋你要觀察的時段。
2. 升降軌方向、觀測模式與視角／軌道組合適合配對。
3. 各日期有共同極化，例如每期都有 HH。
4. 各日期有相同的影格組合，且實際地理範圍重疊。

匯入器會檢查部分條件，但相同 frame 號碼或地圖外框重疊不是可干涉的保證。若一天有 0480、0490，先各自保留完整產品，匯入器再按日期整理；不要以覆蓋同名檔的方式合併。

**日期數：**工作台 alosStack 至少要兩期；MintPy 時序介面至少三期。三期只是入口的最低條件，不能保證可靠速度或季節變化估計。研究仍需要足夠的相干性、連通網路、時間跨度與人工診斷。

**在哪裡取得：**高解析度 ALOS-2 Stripmap 不是全檔案庫公開免費下載。可用研究室合法取得的產品，或依 [JAXA 公開資料與授權說明](https://www.eorc.jaxa.jp/ALOS/en/dataset/alos_open_and_free_e.htm) 查找適用樣本；其他產品依服務商／研究計畫的取得方式與授權使用。JAXA 公開的部分 ScanSAR 或全球鑲嵌圖不能直接替代這條新手 Stripmap 路線。產品層級可查 [JAXA PALSAR-2 格式說明](https://www.eorc.jaxa.jp/ALOS/jp/alos-2/datause/a2_format_j.htm)。

### 準備 B：DEM 與 WBD

| 介面欄位 | 應選擇的東西 |
| --- | --- |
| 對位 DEM | WGS84 橢球高的 ISCE DEM 影像本體，例如 `region.dem.wgs84` |
| 地理編碼 DEM | 適用的 ISCE DEM；若同一份覆蓋充分，可與對位 DEM 相同 |
| 水體遮罩 | ISCE WBD 影像本體，例如 `region.wbd` |

同名 `.xml` 描述檔要隨影像保留，已有 `.vrt` 也需一起保留並有效。**不要只帶 XML，也不要只帶影像而丟掉描述檔。**普通 GeoTIFF、黑白 PNG 或任意水域圖不一定符合這些欄位要求；更改副檔名不能轉換格式或高程基準。

DEM 必須涵蓋完整處理影像，不是只涵蓋最後想看的 MintPy 研究區。工作台會在處理準備時複製並調整專案內的地形描述檔，不需你到 XML 手動改絕對路徑；地形影像本體仍可能連結原本位置，因此原地形磁碟要保持連線。

沒有地形資料時，先完成工作台**專用**工具環境安裝，再選「我還沒有 DEM／水體遮罩」。只選外部既有環境時可使用已準備好的 DEM／WBD，但不會開啟這項管理下載工作：

1. 先完成影像清單與必要的解壓整理，取得影像外框。
2. 使用「帶入全部影像範圍 + 緩衝」或填入完整範圍，再人工核對。
3. 查看下載來源、範圍與空間，確認後下載並驗證。

目前精靈用 **Copernicus GLO-30 DSM／WBM**，並進行所需的高程基準轉換；它不等同課程原有 SRTM DEM／SWBD。自動下載目前限制在絕對緯度不超過 49°、最多 36 個一度圖幅，公開圖幅缺漏時會停止。超出範圍或研究要求不同時，提供已確認適用的完整地形資料。細節見[首次使用的地形說明](FIRST_USE.md)。

### 在網頁中操作

1. 開啟「準備我的 ALOS-2 資料」，選多日期。
2. 用原生選擇視窗選包含整批原始產品／ZIP 的父資料夾。
3. 按「檢查這批資料」，確認日期、產品層級、極化、影格及缺漏。若分成不同候選組合，選你確定要處理的一組。
4. 按「確認清單，整理到工作台」。這不會自動開始干涉運算；等整理完成。
5. 選已有 DEM／WBD，或使用地形下載精靈。
6. 按「帶入設定，確認專案」，選新的工作位置；核對運算環境、參考日期、極化、配對數與電離層選項，再建立專案。辨識時所選環境不一定就是最後帶入專案的環境，請在此再確認。
7. 按「確認設定，準備資料與指令」。工作台依設定產生 XML 與 cmd1–4，檢查環境、資料及地形路徑。
8. 跑到檢查點；若啟用電離層估計／校正，依序完成對應人工判讀與校正後確認。接著做 cmd4 成果驗收，再建立 MintPy 分析與診斷。

「number of subsequent dates」是在一般干涉網路中，每個日期往後配對幾個日期；不是總日期數。工作台會依本次生成的設定使用 looks，不需要從 cmd3 抄六個數字。排除配對與判讀紀錄請在介面操作。

如果你已熟悉 ISCE2，跳過匯入器直接使用進階表單，資料來源則必須是可讀取的日期結構，例如：

```text
source/
├── 240822/    # YYMMDD，兩位年＋月＋日
│   ├── LED-…
│   └── IMG-HH-…
├── 241017/
│   ├── LED-…
│   └── IMG-HH-…
└── 250425/
    ├── LED-…
    └── IMG-HH-…
```

這是**進階直接輸入**的處理結構，不要求新手改掉原始產品資料夾。原始資料仍另行完整保留。

## 5. 其他路線需要準備什麼

### ALOS-2 雙日期

使用相容的兩期同模式 Level 1.1 Stripmap、共同極化／影格，以及配套 DEM／WBD。可沿用上述 ALOS-2 匯入器，選擇雙日期，再帶入「ALOS-2 · 雙日期」。較早日期為 reference，較晚日期為 secondary。

這條路線跑 alos2App，並不會把一組干涉對變成 MintPy 時間序列。相干性、解纏、電離層與參考區仍需判讀。不要把跨衛星資料當作一般同感測器配對。

### Sentinel-1 TOPS 雙日期

到 [ASF Vertex](https://search.asf.alaska.edu/) 選 **Sentinel-1、IW、SLC**。目前工作台入口限定 S1A／S1B，每期一份完整 ZIP 或 `.SAFE` 資料夾；兩期要同相對軌道、同升降軌方向、有共同極化與地面重疊。先註冊／登入免費 Earthdata 帳戶再下載；工作台不代管帳密或下載原始 SAR。

```text
raw/
├── S1A_IW_SLC__…日期1….zip
└── S1A_IW_SLC__…日期2….zip
terrain/
├── region.dem.wgs84
├── region.dem.wgs84.xml
└── region.dem.wgs84.vrt
```

檔名僅示意，請保留下載時原名。也可以使用完整 `.SAFE`，不能只留其中的 measurement TIFF。**課堂洪水分析下載的 GRD 不適用此干涉入口。**

在「建立專案」選「Sentinel-1 TOPS · 雙日期」，分別選兩期產品，按「讀取兩期影像資訊」。選共同極化、連續子波束與 DEM；DEM 須涵蓋兩期完整所選子波束的候選 bursts，不能只覆蓋重疊交集。軌道可選自動 ESA POEORB 或兩期本機 EOF。幾何階段後仍需人工確認共同 bursts。此入口目前不支援 S1C／S1D、多 slice 拼接與單 burst 特例；也不是 TOPS 多日期的替代方案。見 [Sentinel-1 操作與限制](SENTINEL_TOPS.md)。

### ALOS-4 與 ALOS-2／ALOS-4 混合

先看 [JAXA ALOS-4 資料頁](https://www.eorc.jaxa.jp/ALOS/en/alos-4/a4_data_e.htm)，取得相應資料與官方 P3toP2snap 工具。只準備目前支援的**高解析度 Level 1.1 Stripmap CEOS**；該頁其他層級、ScanSAR 等樣本不會因此變成工作台支援產品。

- 每份原始 ALOS-4 產品完整保留 VOL、LED、TRL、IMG，並各自解壓到資料夾。這個批次準備入口讀已解壓資料，與 ALOS-2 ZIP 匯入器不同。
- 在「ALOS 資料準備」選來源父資料夾、官方工具資料夾和新的輸出位置。
- 每份產品在新批次下有獨立子資料夾，例如 `prepared/新批次/日期_產品代號/ALOS2_format/`，並附轉換紀錄。原始來源不變。
- 若與 ALOS-2 混合，先確認影格實際地理對應；在 alosStack 中保留讀取後、匹配前的人工影格及取樣確認。

P3toP2 是格式轉換；統一取樣是調整距離／方位取樣間距。兩者都不能直接證明對位、共同頻帶或跨衛星干涉品質。這條準備路線使用 ISCE2，並非只要看到 ALOS-4 就改用 ISCE3。見 [ALOS 準備](ALOS_PREPARATION.md)及[統一取樣](ALOS_SAMPLING.md)。

### NISAR

此入口需要兩期完整的 **NISAR L-band RSLC `.h5`**、涵蓋完整影像且高程基準正確的 DEM，以及能執行完整 CPU `nisar.workflows.insar` 的**獨立 ISCE3 環境**。現有一鍵安裝的 ISCE2／MintPy 環境沒有包含 ISCE3；只有能 import isce3 也不足以證明整條處理流程可執行。

選同軌道／影格／方向、有共同頻率頻道、極化與重疊的產品。不要選成 GCOV、GSLC、GUNW、STATS.h5 或 PNG。來源放 `raw/nisar/`，輸出另選新的 `projects/nisar_pair/`；沒有先以小研究區裁切原始 RSLC 的新手精靈，需要足夠空間。

官方參考：[ASF RSLC 說明](https://nisar-docs.asf.alaska.edu/rslc/)、[ASF 資料取得](https://nisar-docs.asf.alaska.edu/access-overview/)、[NASA 樣本資料](https://science.nasa.gov/mission/nisar/sample-data/)。樣本可下載不等於已在本工作台通過完整真實資料驗證。選用的水體資料還有特定海岸距離編碼，不能任意用 0／1 水體遮罩替代。詳見 [NISAR 試驗流程](MISSION_LAB.md)。

## 6. 已有成果，如何接續

| 拿到的內容 | 應該做什麼 |
| --- | --- |
| 手動跑完的標準 alosStack `proc` | 「匯入手動 ISCE2 成果」，選 proc 或父資料夾；原磁碟保持連線 |
| 工作台匯出的完整資料包，含 `sar-analysis-package.json` | 「匯入可攜分析資料包」，選整個資料夾，再建新專案 |
| 原本工作台專案，只是外接磁碟換位置 | 使用「重新連結」，不必當作新成果重複匯入 |
| 只有一張 GeoTIFF／速度圖 | 不足以從這個入口重建 MintPy 時序分析 |

標準 alosStack 成果需要完整配對的解纏、遮罩後解纏、相干性、連通區，以及幾何高度、緯度、經度、LOS、WBD，並保留 XML／VRT、track／frame 與 baseline。不是只複製 `pairs` 中一張圖。

手動匯入建立來源連結；可攜包則收集下游分析必要的實體影像，適合帶到另一台電腦。可攜包不含完整原始 SAR、中間 SLC、舊分析版本或 Conda 環境，也不恢復舊 cmd 檢查點。兩種入口都需在接收電腦準備 ISCE2／MintPy 環境，再從品質檢查建立新分析。見[手動成果匯入](LEGACY_IMPORT.md)及[可攜分析包](PORTABLE_PROJECT.md)。

## 7. 開始前最後核對

- 產品的感測器、層級與格式符合所選流程，不是只看副檔名。
- 日期、極化、軌道／觀測組合與實際覆蓋相容。
- 原始來源保留完整，工作輸出是另一個新位置。
- DEM／WBD 的內容與描述檔齊全，高程基準與覆蓋範圍適用。
- 來源與輸出磁碟連線、空間足夠，環境驗證通過。
- 清楚知道要在哪些地方停下來人工判讀。

看到紅色阻擋時，先看具體缺少的資料或設定；不要直接忽略，也不要為了通過檢查而填入沒有確認的日期、影格或參考點。黃色提醒需要理解其影響。完成計算、檔案存在與校驗通過，都不等於研究結果已通過科學驗收。
