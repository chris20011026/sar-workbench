# 可攜分析資料包

把已完成的標準 **alosStack** 成果帶到新位置或另一台電腦，重新建立品質檢查與 MintPy 分析。資料包收集下游分析必要的實體影像，避免只搬工作資料夾後仍依賴舊磁碟的連結。

這是分析交接，不是原始 SAR 前處理與舊檢查點的完整封存。它不包含完整原始 SAR、原始 DEM／WBD、中間 SLC、舊 cmd1–4、執行環境或既有 MintPy 分析版本。若要保存整份研究，仍須另外備份原專案及其外部來源。

## 選擇適合的操作

| 目的 | 使用入口 |
| --- | --- |
| 接回原外接硬碟，重新找到同一個專案 | 管理專案／重新連結 |
| 複製整個既有專案，保留其內容及歷史路徑 | [安全搬移](PROJECT_MIGRATION.md) |
| 在本機讀取手動完成的標準 alosStack 結果，影像留在原位置 | [匯入手動 ISCE2 成果](LEGACY_IMPORT.md) |
| 帶走完整的下游分析輸入，在新位置建立分析 | 可攜分析資料包 |

## 建立資料包

1. 從已完成的標準 alosStack 成果開啟可攜資料包操作，選擇新的存放位置與資料夾名稱。
2. 預覽日期、配對、參考日期、looks、影像大小、需要複製的檔案及可用空間。先確認所有必要影像可讀，原本的處理工作已停止。
3. 核對範圍並確認建立。工作台複製實體影像，重建安全的描述資料，完整計算與核對 SHA-256；大型資料需較長時間。預覽也會讀取完整輸入以驗證內容。
4. 等待完成驗證。未完成或中斷的資料包不能當成可匯入成果。原專案與來源影像保留。
5. 搬動資料包時保留整個資料夾及清單檔，不只複製其中的 `proc`。

資料包是資料夾形式，便於大型 SAR 檔案在外接磁碟間搬移；不會替你上傳網路或發布研究影像。

## 包含的資料

| 類別 | 內容 |
| --- | --- |
| 每一組配對 | 解纏影像、遮罩後解纏影像、相干性及連通區，共四類 raster |
| 幾何參考日期 | 高度、緯度、經度、LOS 與水體遮罩，共五類幾何 raster |
| 描述資料 | 對應 XML／VRT、經限制與重建的 track／frame metadata、baseline |
| 完整性 | 檔案清單、大小、SHA-256 與資料包格式版本 |
| 來源追溯 | 原專案設定、處理與判讀歷史的資料快照；只供查閱，不當成可執行指令或新的品質認證 |

資料包的 XML／VRT 在包內指向對應影像。匯入器不執行包內腳本、不讀取 pickle／shelve，也不沿用來源 XML 中的任意程式元件。來源追溯可能含本機路徑和研究備註；若要分享給其他人，請先確認資料授權與個人資訊。

## 在新位置使用

1. 在接收端工作台開啟可攜資料包匯入，選擇完整資料包資料夾。
2. 選擇一個新的工作資料夾，以及接收電腦上已安裝的 ISCE2／MintPy 環境。資料包不攜帶 Conda 環境，也不安裝或更新既有套件。
3. 等待結構與完整性驗證，核對摘要後確認匯入。相同資料包可以建立獨立專案，舊專案不會被覆蓋。
4. 從新專案執行品質檢查，建立新的 MintPy 分析，重新確認配對、參考點及診斷關卡。

新專案有自己的代號、環境與路徑，不會假裝是原來 cmd1–4 的續跑。來源已有的電離層判讀與處理歷史作為來源紀錄保留；它們不會自動勾選新分析的人工確認。

## 支援與限制

- 限標準 alosStack 已完成的下游分析輸入，使用相同尺寸、單一 looks 與連通的配對網路。各類 raster 及描述資料必須齊全。
- 兩日期可做品質檢查；MintPy 時序介面至少需要三日期。
- 支援範圍不因此擴大到 TOPS 多日期、通用 Stripmap、NISAR 或未完成的跨衛星專案。
- 完整雜湊可驗證檔案內容與清單相符，不能證明影像解纏、電離層校正或位移估計科學上正確。來源宣稱也不是數位簽章或獨立認證。
- 不接續舊 ISCE2／MintPy 檢查點；新分析仍按原本的人工作業關卡進行。
- 這項功能不要求修改原始影像、環境套件或 shell 設定。

## 驗證方式

程式測試應包含獨立複製、完整雜湊、資料變動與中斷拒絕、路徑／連結限制，以及把原來源移走後仍能匯入和讀取。匯入後，每次開始新分析會核對描述檔完整雜湊，並以影像大小、時間、檔案身分與三段抽樣檢查變動；這個快速檢查不等於每次重新計算整幅影像 SHA-256。完整影像雜湊在匯出與匯入時驗證。

原生合成資料驗證另檢查新位置的 ISCE2 metadata 與 MintPy 載入。實際測試結果以發布 commit 的 [Actions](https://github.com/chris20011026/sar-workbench/actions/workflows/validation.yml) 與發布說明為準；合成測試不替代真實研究資料判讀。
