# 分析中斷與恢復

0.6.0 beta 3 提供**主要階段開始前還原、再重跑該階段**。它不是跳過半成品繼續下一行，也不會自動修正失敗原因。

## 平常如何使用

新建的多日期專案預設開啟「保存主要階段開始前的復原副本」。專案的「恢復中心」會顯示狀態與空間說明；可在尚未開始、準備完成或電離層人工判讀時關閉後續保護。舊專案保留原行為，不自動建立巨大的副本，使用者可在上述階段啟用。過去已經失敗的工作不能事後補建失敗前副本。

保存範圍包含 cmd1、cmd2、cmd3 電離層估計、預覽圖片、ion_ls、ion_correct 及 cmd4 的**完整 proc 資料夾**。只有成功保存、逐檔核對且檢查現有 raster 尺寸後，才開始該階段。人工電離層判讀仍然保留。

## 失敗後如何操作

1. 開啟專案的「恢復中心」，按「診斷中斷原因與復原條件」。
2. 核對中斷位置、最後完成階段、最後錯誤及復原點。日誌關鍵字只提供可能原因，不能確定原因時會明確說明。
3. 先處理空間、NAS 連線或權限等問題。不要手動修改指令、排除清單、科學產物或更換環境。
4. 有有效副本時，閱讀復原範圍、勾選確認，再按「驗證副本並復原續跑」。
5. 工作台先驗證副本，再將失敗的 proc 移到專案 `.helper/recovery/<代號>/failed-proc`，並保存 `failed-state.json`。建立獨立工作副本回到原 proc 路徑，從顯示的階段重新執行。原始影像、外部環境和 MintPy 分析不移動。

例如 cmd2 中斷，會回到 cmd2 開始前；cmd1 成果保留。ion_correct 中斷時，會先回到未套用該次校正的副本，再執行校正，避免部分配對被校正兩次。若下一階段尚在建立副本就失敗，可能需要退回前一個仍有效的復原點，介面會顯示實際重跑起點。

## 保護與限制

- 副本中的一般檔案以 SHA256 完整核對，並檢查可辨識的 ISCE imageFile 描述檔尺寸、資料型別與波段數。虛擬 SLC 仍需 ISCE2 執行時讀取；這不是科學正確性或整批 SAR 完整性的認證。
- 大型輸入影像／地形檔核對路徑、連結目標、大小與修改時間；XML、VRT、Conda 套件紀錄及 alosStack Python 腳本另核對 SHA256。不是逐 byte 驗證整個外部 Conda 環境或原始影像；不要在背景編輯或更新它們。
- 設定、指令、排除清單或輸入紀錄改變，副本損壞，未知外部連結，或仍有原工作台留下的子程序時，拒絕恢復。外部手動啟動的運算不在程序追蹤範圍；不要讓其他程式同時寫入專案。
- 每個專案只保留**最新可用階段前副本**；新副本驗證並保存成功後才清除前一份。失敗半成品不自動刪除。首次復原會增加一份保留資料；多次失敗會累積。
- APFS 優先使用 copy-on-write 獨立副本；不支援時完整複製，**不使用會連動修改的硬連結**。為保守起見，即使 APFS 可共享區塊，仍要求至少完整 proc 邏輯大小加 1 GiB 的可用空間。實際科學運算另外需要空間。
- 完整雜湊會增加磁碟 I/O，NAS 和大型專案可能花很久。畫面會顯示正在保存或驗證，這段時間尚未开始該階段科學運算。
- 副本搬移若遭服務中斷，保留搬移紀錄；下次明確按復原時核對並完成搬移。不能判定一致性時停止，不猜測或覆蓋。
- 雙日期、自訂 shell 指令與手動接管舊 proc 不包含在此恢復功能。沒有副本時仍可查看診斷，不會提供不安全的重試按鈕。

## 驗證範圍

自動測試模擬 cmd2、電離層校正與 cmd4 失敗，核對先前階段不重算、校正不重複、半成品保留、變更與損壞阻擋、取消、空間不足、存活程序，以及復原搬移中斷。瀏覽器測試使用隔離的合成檔案和模擬運算；不拿使用者的完整研究專案測試破壞或回滾。


## MintPy：建立恢復版本

0.8 beta 6 起，新執行的 MintPy 分析會在載入、解纏診斷、反演與校正、最終速度這些主要階段開始前保存一份完整副本。已完成的版本不會被回溯補建副本。

1. 打開已停止的 MintPy 分析，按「檢查可恢復階段」。
2. 工作台核對原始輸入、參數、專案位置、環境與程式版本、磁碟空間，以及副本的 SHA256 完整性。
3. 勾選確認，按「建立恢復版本」。原失敗版本保持原樣，複製未完成時不會出現可繼續的分析版本。
4. 若載入階段失敗，新版本會重新載入；其他階段回到參考點、解纏或殘差的人工關卡，再由你確認下一步。

每個分析保留最新一份階段前副本。副本會增加磁碟用量；APFS 優先使用獨立的 copy-on-write 副本，其他檔案系統完整複製，並保守要求副本邏輯大小加 64 MiB 的可用空間。失敗版本與恢復版本都保留，不會自動清理。副本不等於外接硬碟故障時的異地備份。

恢復不重用失敗階段的半成品，不會把校正套用兩次。曾經的判讀保留在來源與恢復紀錄中，當前關卡仍需重新確認。沒有副本、輸入或環境改變、副本不完整、背景程序尚存或專案搬移後未重新建立可運算位置時，會拒絕恢復。

驗證包含原生 MintPy 合成資料流程、在原生步驟之間終止實際子程序、重開服務、恢復及數值一致性；另測複製／重建中斷不發布未完成版本。這不代表任意運算核心內部崩潰、硬碟損壞或突然斷電都已驗證。
