# SAR 研究工作台（SAR Workbench）

新增：ALOS-2 正式中繼資料核對、候選分組、影像覆蓋地圖與地形範圍帶入。使用方式與限制見[影像匯入說明](docs/IMAGE_IMPORT.md)。


本機執行的視覺化 SAR 處理介面，沿用 ISCE2 與 MintPy 的科學運算核心。目前版本 **0.6.0 beta 6**。新增 [Sentinel-1 TOPS 雙日期試驗流程](docs/SENTINEL_TOPS.md)：SAFE／ZIP 辨識、選区、精密軌道、共同 burst 檢查與階段執行。尚未完成真實 SLC 端到端驗證。

**第一次使用（Apple Silicon Mac / macOS 14.5+）**：到 [下載頁](https://github.com/chris20011026/sar-workbench/releases/tag/v0.6.0-beta.6) 取得 Mac App，解壓縮後雙擊。啟動器會準備必要工具，再由網頁安裝並驗證固定版本的 ISCE2、MintPy、SNAPHU。**不需要先安裝 Python、Conda 或使用終端機**；首次安裝需要網路、下載時間與至少 12 GB 工具空間。此測試版尚未 Apple 公證，初次開啟可能需 macOS 確認。

[第一次使用指南](docs/FIRST_USE.md) · [0.6 更新與驗證方式](docs/RELEASE_0.6.md) · [自動測試紀錄](https://github.com/chris20011026/sar-workbench/actions/workflows/validation.yml)

首頁提供合成教學、ALOS-2 ZIP／資料夾匯入與公開地形下載。真實 SAR 影像仍需自行取得，科學參考點與電離層品質仍需判讀。自動安裝使用 [insar-arm](https://github.com/chris20011026/insar-arm) 的固定套件，放在工作台專用資料夾；既有 Conda 環境與研究專案保持原設定。

**已有科學環境／從原始碼啟動**：

```sh
git clone https://github.com/chris20011026/sar-workbench.git
cd sar-workbench
PYTHONPATH=src python3 -m alosstack_helper.server
```

啟動後以一般瀏覽器開啟 `http://127.0.0.1:8765/`，不需要 ChatGPT 或 Codex。這是本機 Python 伺服器，無法用 GitHub Pages 執行 SAR 運算。原 Python 套件名稱與指令 `alosstack-helper` 保留相容性。

本機瀏覽器操作的 ISCE2 / ALOS-2 工作台。使用表單建立專案，執行到電離層檢查，再用圖片旁的核取方塊選擇壞配對。工具不自動判讀科學品質。

## 從原始碼啟動

需要 Python 3.10+，Web 介面本身沒有第三方依賴。macOS 可雙擊 `start.command`；或在此資料夾執行：

```sh
python3 -m pip install -e .
alosstack-helper
```

無需安裝套件的方式（macOS / Linux）：

```sh
PYTHONPATH=src python3 -m alosstack_helper.server
```

瀏覽器會開啟 http://127.0.0.1:8765 。僅供可信任的本機使用者使用，不要代理到網際網路。關閉分頁不會停止後端運算；必須保持伺服器運作。停止工作請用畫面上的按鈕。勿在運算中關閉終端機或讓電腦睡眠。

macOS 上的「選擇」與「匯入 XML 範本」預設開啟系統原生選擇視窗，可使用側邊欄、搜尋、已掛載 NAS，以及 ⌘⇧G 前往路徑。取消不會更改欄位；會從目前欄位附近的資料夾開始。首頁可改選「網頁內建選擇器」，其他系統自動使用內建版本。

## 處理範圍與資料保護

- macOS / Linux 為目標平台；開發驗證使用 macOS。Windows 原生不支援，可在 WSL 內另行驗證。
- 可由 Mac App 安裝專用環境，或自行選擇可工作的 Conda ISCE2 環境，內含 `share/isce2/alosStack`，及 `mdx`、ImageMagick `montage` 等上游工具。使用 `conda run` 啟動環境，並為子程序加入該環境的 ISCE_HOME/bin、ISCE_HOME/applications 與 alosStack 搜尋路徑，不修改原環境套件或 shell 設定。
- 新建專案；不接管既有 `proc` 或覆蓋既有成果。
- 引擎讀取 `YYMMDD/LED-ALOS2...`、`YYMMDD/IMG-...ALOS2...`。0.6 匯入精靈可掃描巢狀資料夾與 ZIP，整理到新的日期目錄。跨軌道自動分組尚未實作；混合產品會要求先分組。
- 可直接讀取來源，或 rsync 複製到專案並 SHA-256 比對。大型檔案完整驗證需要時間。NAS 需事先掛載。
- DEM/WBD 需含同名 XML，內容和覆蓋區域由研究者確認。0.6 可取得 Copernicus DSM/WBM 並转換高程與格式，也可選既有地形檔；詳見首次使用指南。準備時會在專案 .helper/inputs 建立原始 raster 的符號連結，複製並修正 XML 的 file_name，以及 VRT 的 SourceFilename，來源 raster/XML/VRT 均不修改。XML 其他內容保留，複雜 VRT 外部來源會停止要求確認。專案仍依賴原始資料位置。
- 路徑限 ASCII 字母、數字、`/._-`；這是上游生成 shell 指令未完整引用路徑的限制。
- 匯入 XML 後可用表單修改 property。輸出位置由工具固定在專案內；電離層估計與校正各有「使用程式預設值／啟用／關閉」三個選項。未設定的參數不寫入 XML，準備階段由目前安裝的 ISCE2 解析實際預設值並顯示摘要。關閉估計時執行 cmd1、cmd2、cmd4；僅關閉校正時保留電離層估計、判讀與 ion_ls，跳過 ion_correct。兩個旗標組合與上游一致：估計關閉時，即使校正旗標啟用也不套用校正。
- 保留原始 cmd1～4。從明確的 upstream 段落拆出 cmd3 前段；不認識的結構會停止。後段使用解析的 `ion_ls.py` 參數，指定 `-exc_pair`，並逐對呼叫 `ion_correct.py`。
- 排除清單會檢查配對網路連通性及待校正日期涵蓋。沒有自動壞日期排除，避開目前安裝版本 `-exc_date` 的說明/實作差異。
- 運算錯誤即停止並保留產物，不自動重試。準備失敗且未進入科學運算可手動重新準備；ALOS-2 多日期新增[恢復中心](docs/RECOVERY.md)，有有效的階段前副本才可確認還原並重跑該階段。改變設定或排除清單後不能直接使用原副本。不要用新建專案覆蓋半成品。
- 完成檢查涵蓋程序退出碼、電離層必要產物及地理編碼解纏檔存在且非空；不代表科學品質合格或完整的數值驗證。

## 資料位置

程式與研究資料分離。每個專案：

```text
project/
  data/                 # 選擇複製時才建立
  proc/alosStack.xml
  proc/cmd_1.sh ... cmd_4.sh
  proc/fig_ion/
  .helper/state.json    # 階段、參數、指令指紋
  .helper/run.log
  .helper/review.json   # 判讀紀錄與實際 ion_ls 指令
  .helper/report.json  # 完成時產生
```

本機專案索引預設在 `~/.local/share/alosstack-helper`，可用 `--state-dir` 更改。分享本工具時不需要分享上述研究資料，也請不要上傳包含私人路徑的紀錄。

## 常用 XML 參數的畫面對應

| XML property | 網頁欄位 |
| --- | --- |
| data directory | 專案與資料 → ALOS-2 資料資料夾（選擇複製時，XML 改指向專案內的 data） |
| dem for coregistration | 環境與地形資料 → 對位用 DEM |
| dem for geocoding | 環境與地形資料 → 地理編碼用 DEM |
| water body | 環境與地形資料 → 水體遮罩 WBD |
| reference date of the stack | 專案與資料 → 參考日期 |
| polarization | 處理設定 → 極化方式（polarization） |
| number of subsequent dates | 處理設定 → 一般配對：後續日期數 |
| do ionospheric phase estimation | 處理設定 → 估計電離層 |
| apply ionospheric phase correction | 處理設定 → 套用電離層校正 |

極化下拉選單提供 HH、HV、VH、VV 與使用程式預設值。必須與資料實際包含的極化一致；列出選項不代表每一種資料都支援該極化。匯入的其他值會原樣呈現供確認，不會默默改成 HH。

## 選用的本機繪圖相容環境

工作台可讀取安裝資料夾內的 `.runtime/bin` 繪圖啟動器，以支援特定舊環境。這是個別電腦的選用安裝產物，未隨此專案散布；一般安裝直接使用所選科學環境提供的 mdx、montage 與 convert。請依自己的平台安裝相符架構的工具，不要複製其他電腦的函式庫。

準備專案時會實際繪製小型圖片，檢查 mdx 載入、字型與影像轉換。原科學環境套件與 shell 設定不由工作台修改。

## 0.2：品質檢查與 MintPy

入口現在列出六種處理方式。0.2 開放 alosStack；0.4 另加入 alos2App 的 Stripmap 雙日期試用。topsApp、topsStack、stripmapApp、stripmapStack 明確標示規劃中，伺服器也拒絕尚未支援的模式。

已完成的 alosStack 專案可在「成果品質 / MintPy 分析」區操作：

1. 選擇分析環境。建議使用已驗證的原生 ARM `insar_arm`；畫面同時顯示原干涉處理環境，兩者互不替換。
2. 「重新檢查成果品質」驗證雷達影像尺寸及描述檔、檢查相干性和解纏数值，產生配對表、陸地保留率、共同覆蓋圖、相干性及相位預覽。可下載 CSV / JSON。非零解纏比例不是準確率。
3. 「MintPy 分析」選時間參考日期、記憶體上限、時間相干性及參考點門檻，選擇是否移除坡度、估計殘餘 DEM 誤差。可另行排除 MintPy 配對；**不繼承電離層估計的排除清單**。開始前檢查所有日期的網路連通。
4. 按「檢查並載入資料」後停在檢查點。畫面顯示共同陸地覆蓋與高相干候選參考點，可直接點選平均相干性圖。行／列座標相對於本次載入範圍，以 0 起算。
5. 確認配對、覆蓋與參考設定後才啟動反演。參考點必須是所有保留配對共同有效的陸地，且平均相干性達門檻；不合格時保留載入階段供重新選擇。
6. 完成後檢視 LOS 平均速度、時間相干性；點圖讀取日期位移曲線，匯出點位 CSV、速度 HDF5 與本次設定。

### 資料保護與範圍

每次分析建立 `project/analyses/<id>/`，含分析設定、來源檔案大小／時間戳及描述檔 SHA256、日誌、版本、成果。原始 `proc` 保持不變。分析私有 `source` 內複製 track/frame/XML/VRT/baseline，影像以符號連結讀取，MintPy 產生的 `.rsc` 只寫在分析內。來源位置須保持可讀。每次開始/結束及進入反演前核對來源指紋；不把失敗結果標為完成，不自動覆寫半成品。

此版本提供雷達座標下的**基礎時序流程**。預設不進行氣象下載、大氣校正、固體潮、二次電離層校正或解纏錯誤修正。空間坡度與 DEM 誤差校正由表單明確選擇。0.3 已新增地圖、地理編碼與 GeoTIFF 匯出（見下節）；KMZ、其餘 ISCE2 工作流及遠端佇列尚未實作。原有 ISCE2 電離層校正是否啟用保留在分析紀錄中。位移/速度為相對空間參考點及時間參考日期的 LOS 值：正值朝向衛星，負值遠離衛星，不能直接等同垂直沉降。

分析與原 ISCE2 運算共用同一個工作鎖；停止按鈕停止所啟動的子程序。中斷後保留診斷紀錄並另建分析版本，不會偷偷接續半成品。多個伺服器同時操作同一專案不受支援。

## 0.3：範圍地圖與成果判讀

已完成的舊專案也能直接使用新版地圖，不必重跑 ISCE 或 MintPy。

- **範圍**：在 MintPy 表單載入涵蓋範圍，點選矩形兩個對角，或輸入南北西東經緯度。預覽顯示真正送入 MintPy 的雷達矩形；它可能稍大於所畫地理矩形。四個欄位留白使用完整影像。數值像素裁切仍在進階設定；兩種裁切方式不能同時指定。
- **日期與配對**：指定起訖日期、保留日期，或排除配對；伺服器重新檢查保留日期的網路。至少保留三期。畫面列出時間間隔、中心垂直基線差和最新品質報告的全域陸地相干性中位數，可套用篩選建議；這些品質數值不是所框 ROI 的統計。
- **反演**：提供相位變異數 / Fisher 資訊 / 相干性 / 不加權，以及最低冗餘。DEM 誤差校正可選一次、二次時間模型並檢查最低日期數；這項檢查不代表基線及模型具備充分可辨識性。0.3 的速度估計維持線性；0.5 新增時間模型與不確定度選項，詳見下節。
- **地圖**：以 pyresample 最近鄰與 ISCE 經緯度查找表建立 Web Mercator 顯示網格；每格保存對應來源像素，顯示及選點使用同一對應。不將雷達 PNG 當作經緯度矩形拉伸。地圖初始聚焦有效成果，可回到全部涵蓋範圍。
- **底圖**：預設使用本機高程資料的灰階底圖，不發送外部圖磚請求。手動選擇 OpenStreetMap 才會依觀看範圍向該服務要求圖磚；SAR 影像不會上傳。網路底圖有來源標示，離線時仍可使用本機成果。
- **品質與顯示**：速度、不確定度、時間相干性與分類遮罩可切換；可調整色階及透明度。顯示門檻只能在本次原始品質遮罩上加嚴，不會修改反演或恢復已被原始遮罩排除的點。
- **選點與曲線**：提供地圖點選與座標輸入；前者使用顯示網格對應，後者直接查找最近的原始像素，不經過預覽降採樣。標記實際讀取的來源像素。完整日期軸、零線、參考日期、懸停數值、縮放、PNG 和含座標/參考資訊的 CSV。無效選點會清除舊曲線並停用匯出；較早的非同步回應不能覆蓋較新的選擇。
- **輸出**：GeoTIFF 支援 WGS84 與臺灣 TWD97 / TM2 121，20–2000 m 的輸出像素設定，最近鄰取值，速度與標準差以 mm/year 輸出，NoData 為 NaN。WGS84 的公尺大小是依研究區緯度換算的近似值。圖像 PNG 含地理座標刻度、色階、參考點、單位與分析代號；使用離線底圖。選擇細網格不增加原始解析度。
- **版本**：可命名、複製設定建立新分析、比較設定。所有計算參數變更都建立新分析；顯示與匯出只建立衍生檔案。

原始 `proc` 及原有 HDF5 以唯讀方式開啟。地圖快取寫在 `analyses/.map-cache`（範圍預览）及各次分析 `exports` 內。GeoTIFF、地圖 PNG 與查找網格均屬衍生資料。單個地理輸出限制為 1,200 萬像素。跨換日線的資料目前會明確拒絕。多邊形/GeoJSON、衛星影像底圖仍屬後續範圍；0.5 新增進階大氣與解纏校正控制。

本版供應本機 Leaflet 1.9.4（BSD-2-Clause）與 Plotly basic 2.35.2（MIT），授權文字位於 `static/leaflet.LICENSE` 與 `static/plotly.LICENSE`。科學環境需已有 numpy、h5py、pyproj、pyresample、matplotlib、Pillow；GeoTIFF 另需 GDAL。沒有變更使用者 Conda 環境。

## 0.4：ALOS-2 雙日期（alos2App）試用

首頁可選「ALOS-2 · 雙日期」。此 adapter 沿用所選環境的官方 `alos2App.py`，按 upstream 的 25 個命名步驟執行，不修改 ISCE2 或 Conda 套件。第一版開放同觀測模式、相同極化與方向的 **ALOS-2 Level 1.1 Stripmap / Stripmap**；其他產品與混合模式明確拒絕。已用 FBD / HH / frame 0480 的真實配對驗證，不能據此宣稱所有 Stripmap 產品或平台都驗證過。

操作順序：

1. 選資料來源、兩個日期（早期 reference、晚期 secondary）、共同 frame。可只選部分共同 frame；複製選項只複製本次選定的 LED / IMG，不複製其他日期或極化。
2. 選 Conda、兩份 DEM 及 WBD。新建空專案後，先驗證參數、安裝版本及必要工具；原始地形描述檔不修改。來源大小、時間戳與描述檔雜湊保留供後續檢查。
3. 「讀取兩期影像，檢查基線與範圍」只執行 startup、preprocess、baseline，顯示軌道、波長、中心垂直基線、六個實際 looks 與 DEM 底圖上的兩期外框。檢查方向、外框交集、地形資料涵蓋範圍。
4. 確認後開始干涉處理。若開啟電離層估計，在 ion_filt 完成後停下。介面提供完整估計、標準差、視窗、上下子頻帶相位，以及相干性和有效陸地預覽。後者採 land + coherence ≥ 0.3 + 兩子頻帶有效連通區，只影響顯示，不改科學產物。
5. 人工勾選確認，選擇套用或保留估計但不套用，再接 ion_correct、filt、unwrap、geocode。此決定另存 `alos2App.review.xml` 和判讀紀錄，原始設定保留。關閉估計時略過人工檢查，上游 ion 步驟為 no-op，仍保存連續檢查點。
6. 完成後檢查相干性、有效陸地保留率、連通區與數值問題；用離線 DEM 底圖查看解纏相位 / 相干性 / 電離層，下載 WGS84 GeoTIFF、JSON 與實際設定。線上道路底圖須手動選擇，預設不連外。

表單提供極化、電離層兩個旗標、六個 looks、共同覆蓋裁切、濾波強度 / 視窗 / 步距、水體遮罩起點、地理編碼插值、電離層濾波視窗與最終輸出範圍。**地理編碼範圍只限制最後輸出，不縮小前面的對位與干涉运算**。支援匯入 alos2insar XML 中已開放的參數；未知參數報錯，不靜默忽略。輸入資料與 frame 重新在表單選擇，輸出路徑、CPU / InSAR / virtual-file / checkpoint 設定由工作台管理。

雙日期成果目前以 **解纏相位 rad** 呈現，尚未提供穩定空間參考點與 LOS 位移換算，亦不提供單一配對的 MintPy 時間序列。相位可能含大氣、軌道、地形和解纏誤差；高保留率不代表高準確率。此限制在成果頁明示，沒有把相位直接標為位移或年速度。

執行前核對來源與設定指紋，步驟間核對上一個 ISCE2 XML / pickle 檢查點；必須按序完成。任何程序失敗立即停止，保留產物，不重跑可能寫了一半的步驟。只有尚未建立科學檢查點的準備失敗可重新準備。中斷後自動續跑與重用部分科學產物不在本版範圍。雙日期模式與原 alosStack / MintPy 共用工作鎖，原多日期專案不轉換、不覆蓋。

新增檔案：`pair.py`（驗證、設定、階段控制）、`pair_worker.py`（科學環境內的檢查與衍生圖）、`static/pair.js`（雙日期介面）。專案沿用 `proc/` 與 `.helper/`；報告與瀏覽器成果存在 `.helper/pair-exports/`。

## 0.5：MintPy 三層設定與方法紀錄

MintPy 分析表單分為三個頁籤，沿用既有的載入 → 確認參考點 → 反演流程：

- **常用設定**：研究範圍、觀測日期、時間參考日期、品質門檻、記憶體、配對檢查與基本校正。原有欄位與地圖操作保留。
- **進階設定**：依處理階段分組的校正方法、原生網路篩選、遮罩、反演控制、DEM / 時間模型與不確定度。每個欄位可展開中文用途、適用條件、取捨及官方文件／研究來源。
- **全部參數**：以本次盤點的 MintPy 1.6.4.post3 主流程範本為基準，列出 **121 項**，支援關鍵字、類別與狀態篩選。其中 **17 項對應既有欄位、54 項提供進階編輯**；其餘由工作台管理或尚未開放，顯示原因。這不是 MintPy 所有獨立命令列工具的全集，也不代表 121 項都能任意修改。

每個參數只有一個設定來源；全部參數頁會跳回對應欄位。「沿用工作台基準」保留原有行為；「MintPy auto」由所選環境的官方預設解析，可能會啟用方法，**不等於關閉**。工作台讀取所選環境的版本與範本，遇到缺少參數或版本差異會提示並於執行前檢查。設定變更只用於新分析，舊成果仍可瀏覽、複製設定與比較。

### 可選方法與限制

- 解纏錯誤修正：橋接、相位閉合、先橋接再閉合。會檢查套件、連通區及三角配對等前提；方法選擇不等於解纏錯誤一定被修好。
- 固體潮：依已安裝的 PySolid、幾何與擷取時刻執行。
- 對流層：高程相關、GACOS 或 PyAPS / ERA5。GACOS 必須有全部保留日期的延遲與描述資料；ERA5 必須先具備正確範圍、日期和時刻的 GRIB 快取。本版不下載氣象資料或設定服務帳密。外部輔助檔複製到本次分析內，保留來源大小／時間戳記供核對。
- 電離層：沿用上游 alosStack 產物及其校正紀錄；本版未開放 MintPy 再次校正，避免假設已備妥獨立電離層輸入。
- 時間模型：線性／高階多項式、週期、階躍、指數及對數項。以實際保留日期檢查設計矩陣的秩與殘差自由度；DEM 模型另檢查基線項。日期很少時不能任意增加參數。
- 不確定度：擬合殘差、純線性模型 Bootstrap，以及具有相符日期、網格與 m² 單位的逐日期變異數資料。當前轉接僅支援 N×Y×X 對角變異數；N×N×Y×X 完整共變異數會拒絕，不會靜默退回另一種估計。
- 原生多視、平行運算、其他輸入處理器、OPERA 及 MintPy 原生地理輸出仍有整合限制；工作台地圖與 GeoTIFF 繼續使用既有輸出流程。進階頁的原生網路門檻會實際交給 MintPy；常用頁「套用篩選建議」只調整配對排除清單，兩者有清楚區別。

每次分析保存 `parameter-report.json`：MintPy 版本、要求值、解析後的值、外部輔助檔紀錄、模型與參與擬合日期、設定指紋，以及各校正的等待／執行／完成／失敗狀態。只有原生步驟完成且確認預期產物才標示完成；這不代表科學準確性通過認證。報告可在介面檢視並於完成後下載。

加入季節性、事件或高階項後，速度圖會標為 **LOS 模型線性項係數**；不是整段觀測時間的單一直線平均速度。時間曲線仍呈現全部觀測日期，報告另列實際參與擬合的日期。新圖像與 GeoTIFF 附上模型含義與不確定度方法。
